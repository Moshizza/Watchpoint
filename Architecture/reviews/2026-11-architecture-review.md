# Architecture consistency review — 2026-11-15

Read-only review of `Architecture/` against the code merged on `main` (up to `013848f`, T1.09b).
Reviewer: `claude-iris`. Nothing outside this file was changed. The architect applies the fixes.

Columns: **Severity** H/M/L. **Tier** 1 = pure consistency (docs must match code or each other,
meaning unchanged: apply mechanically). Tier 2 = changes intent, a contract, a guarantee or the
plan: options and a recommendation are given instead of an exact fix.

## Top 10

1. (1.1, H) `tasks.md` lists **T1.09b twice and T1.10 twice** with contradicting rows (one `done`, one `todo`, different test ranges); `next-task.py` and readers see a `todo` T1.10 that is merged.
2. (2.2 + 4.1, H) REG §5/§6 contract ≠ code (`IRegistryReader` members, `RegistryChange` cases, `ChangeContext`, REG-local `Page<T>`/`PageRequest` duplicating Kernel's). STA (T1.11), API (T1.19) and CFG (T3.01/T3.02) are specified against the spec shape: decide before T1.11 starts (recommendation: `T1.07c`).
3. (2.3 + 4.2, H) REG §9 error catalogue (20 codes) vs code: writer emits `registry.entity_not_found`, `common.version.conflict` and one generic invariant error; plain-language problems (API §5, UIF §6) key on the codes. Recommendation: code follows spec in `T1.07c`, plus a per-module code-catalogue test.
4. (4.6, H) Public repository: every development relaxation (`Node:Environment=Development` → unauthenticated `POST /api/v1/packages`, `devtoken`, `Log:AllowInsecureRemote`, dev-key trust, seed passwords) is now readable; the specs never state how production installs are prevented from running in Development, and `docs/operations/security.md` (cited by the security test plan) does not exist.
5. (1.6, M) Hand-offs of T1.10/T1.09b tracked nowhere: last-value purge for deleted devices, dev-seed site/locations/tags steps, outbox record size check before commit, `IIngestFloodingListener`/`ILastValueSource` implementers.
6. (1.5, M) T1.17b depends on CMD verification (MQTT-I-004) but its Deps omit T2.03; T4.05c re-lists MODB-I-001/003/006 that T4.05 (done) claims.
7. (3.1, M) Partition subscriber `Order 450` is used by both NOT and SCR; PIP §7.3 lists only STA/CMD/ALM/AUT. STA's snapshot-restore start-up task has no order relative to `PipelineRecovery` (Recovery, 100).
8. (2.6 + 3.3, M) IRT §12/§13 stale (5 error codes, events 1805–1816 missing); IRT event range 1800–1999 overlaps IHO 1950–1999; 33 specs declare no event-id range and README §10 lacks Secrets, Scheduling, Maintenance, Cluster, Health, Federation, Files, Synoptics rows.
9. (2.8, M) HST §14 note / §9 say the Registry module is not in the host catalogue; it is. Only the REG seed steps are missing.
10. (4.4 + 4.7, M) Scale and durability: ADR-001 throughput was measured at R1 only (CLU runs R3); JetStream `MaxBytes` reservation silently shortens `Log:Retention` on small disks; `DenyDelete/DenyPurge` + `Log:Retention` up to 90 days contradicts HIS §12 privacy purge for event payloads.
