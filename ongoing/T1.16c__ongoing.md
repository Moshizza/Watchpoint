### 2026-11-27T19:40Z claude-pavo
Fix implemented (DeviceMap.Ready/MarkReady/BecameReady + ObservationSink defer/replay, no public
contract change) and pushed. Added IRT-U-067…069 directly on ObservationSink+DeviceMap (new
`SinkWithEmptyMap` test helper, mirroring the existing `Sink` helper's pattern). Caught and fixed
two issues before pushing the final version: (1) the existing `Sink()` test helper needed an
explicit `MarkReady()` too — it preloads a fully-populated map and expects immediate
resolve-or-unknown semantics, unrelated to the connect race IRT-U-067…069 exercise; (2)
`FlushAsync`'s wait was keyed on `_seq`, which a deferred report never bumps, so a flush
immediately after a deferred report could return before the deferred report's eventual outcome
(accepted or unknown) landed — found via IRT-U-048 flaking at a much higher rate than this
sandbox's known pre-existing timing flakes (confirmed unmodified `main` flakes too, just far less
often, ~1/15 vs ~8/10 before this fix). Added a `_deferredDrainedWaiters` list so `FlushAsync`
waits for any pending deferred reports to resolve before computing its result. Re-verifying with
repeated runs now; will update the PR checklist and this file to `waiting-approval` once green.
